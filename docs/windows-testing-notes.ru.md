Найдено и исправлено:

- `DC_DUPLEX/DC_PAPERNAMES/DC_PAPERS` есть в `win32con`, а не в `win32print` —
  из-за `except: pass` размеры бумаги и дуплекс молча пропадали.
- `OpenPrinter(PRINTER_ALL_ACCESS)` → «Отказано в доступе» у
  неадминистратора, из-за чего падала любая печать. Теперь настройки
  пишутся в пользовательский DEVMODE (`SetPrinter` уровень 9), достаточно
  `PRINTER_ACCESS_USE`.
- `win32api.ShellExecute` при ошибке бросает исключение, а не возвращает
  код ≤32 — был HTTP 500 вместо задания со статусом `failed`.
- PDF по умолчанию открывался Firefox, у которого нет `printto` — теперь
  PDF рендерится через `pypdfium2` (`FPDF_RenderPage` в printer DC) с
  настройками на задание.
- Starlette 1.x: `TemplateResponse(name, {"request": ...})` больше не
  работает → `TemplateResponse(request, name)`.
- Автоперезагрузка uvicorn на Windows оставляла старый воркер и следила за
  `.venv` — теперь выключена по умолчанию (`MFP_RELOAD=1` для разработки).

## Контекст проекта

MFP Print & Scan Server — веб-сервер (FastAPI) с загрузкой файла на печать через
браузер. Работает и на Linux (CUPS), и на Windows (системная печать),
бэкенд выбирается автоматически по ОС в `app/printing/factory.py`.

- `app/printing/base.py` — абстрактный интерфейс `PrintBackend`
  (`list_printers`, `list_options`, `print_file`).
- `app/printing/linux_cups.py` — CUPS-реализация. **Полностью
  протестирована** на реальном принтере (Canon MG2541 через CUPS), работает
  корректно.
- `app/printing/windows_print.py` — Windows-реализация через `pywin32`.
  **Не протестирована.** Это то, что нужно проверить.

Настройки печати (размер бумаги, тип, качество, цвет, дуплекс) не
захардкожены — сервер запрашивает их у самого драйвера принтера через
`list_options()`, чтобы любой новый МФУ работал без правок кода. На
Windows это делается через `win32print.DeviceCapabilities`.

## Что нужно на Windows-машине

1. Windows 10/11.
2. Python 3.11+ с python.org (при установке отметить "Add python.exe to
   PATH").
3. Принтер уже установлен и виден в "Параметры → Bluetooth и устройства →
   Принтеры и сканеры", и обычная печать через проводник (правой кнопкой
   по файлу → "Печать") на нём работает — то есть драйвер в системе рабочий.
4. Скопировать папку проекта на Windows-машину (например, через флешку,
   сетевую шару или `git clone`, если репозиторий уже в git).

## Установка и запуск

```powershell
cd путь\к\MfuServer
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python run.py
```

Открыть http://localhost:8000

Если `pip install` ругается на `pywin32` — переустановить отдельно
(`pip install pywin32`) и один раз выполнить
`python .venv\Scripts\pywin32_postinstall.py -install` (иногда нужно для
корректной регистрации COM/win32-хуков).

## Чек-лист проверки (от простого к сложному)

### 1. Список принтеров — `GET /api/printers`

Открыть `http://localhost:8000/api/printers` в браузере.

- Ожидается: JSON-список всех принтеров Windows, у принтера по умолчанию
  `"is_default": true`.
- Код: `WindowsPrintBackend.list_printers` в
  [app/printing/windows_print.py](../app/printing/windows_print.py) — использует
  `win32print.EnumPrinters` и `win32print.GetDefaultPrinter()`. Простой,
  низкий риск поломки.

### 2. Настройки принтера — `GET /api/printers/{name}/options`

Подставить реальное имя принтера (если с пробелами — URL-кодировать, browser
сделает это сам при переходе по ссылке из выпадающего списка в самом UI).

- Ожидается минимум: `quality` (Черновик/Обычное/Высокое) и `color`
  (Цветная/Чёрно-белая) — они не зависят от драйвера и должны быть всегда.
  Если принтер поддерживает дуплекс — появится `duplex`. Обычно должен
  появиться `paper_size` со списком реальных размеров этого принтера.
- **Риск:** вызовы `win32print.DeviceCapabilities(printer_name, port,
  win32print.DC_DUPLEX / DC_PAPERNAMES / DC_PAPERS)` в
  `WindowsPrintBackend.list_options` — сигнатура и точное поведение этой
  функции в pywin32 проверялись только по документации, не вживую. Ошибки
  там перехватываются (`except Exception: pass`), поэтому при сбое просто
  тихо не будет `paper_size`/`duplex` — это надо заметить и разобраться, а
  не считать нормальным поведением. Если запрос вернёт 500 — смотреть
  traceback в консоли, где запущен `uvicorn`, там будет точная причина.

### 3. Обычная печать — `POST /api/print` (через веб-интерфейс)

⚠️ Это реальная печать, тратит бумагу — предупредить того, кто тестирует.

Загрузить простой `.txt`, нажать "Печать" с настройками по умолчанию.

- Ожидается: файл реально печатается, в истории заданий — `status: "sent"`.
- **Главный риск:** UI всегда шлёт хотя бы `quality` и `color` (они есть
  всегда, см. п.2), поэтому `_apply_devmode()` вызывается при КАЖДОЙ печати
  ещё до того, как файл уйдёт на принтер. Внутри неё:
  - `win32print.OpenPrinter(printer_name, {"DesiredAccess":
    win32print.PRINTER_ALL_ACCESS})` — может потребовать больше прав, чем
    есть у обычного пользователя (для домашнего принтера обычно ок, но не
    гарантировано). Если тут `Access Denied` — см. раздел "Известные
    компромиссы" ниже про снижение прав.
  - `win32print.DocumentProperties(...)` — здесь уже был один найденный и
    исправленный баг (неверные флаги `fMode`: было `3`, должно быть
    `DM_IN_BUFFER(8) | DM_OUT_BUFFER(2) = 10`, поправлено в текущей версии
    файла) — стоит перепроверить, что вызов не бросает исключение на
    реальном драйвере.
  - После печати имеет смысл заглянуть в "Свойства принтера" и убедиться,
    что настройки по умолчанию не стали "битыми" (сервер их подменяет перед
    печатью, см. ограничение ниже).
- **Второй риск:** сама механика `win32api.ShellExecute(0, "printto",
  str(file_path), f'"{target}"', ".", 0)` работает только если у типа
  файла в реестре Windows зарегистрирован print-verb ("Печать" в контекстном
  меню проводника). Для `.txt` есть почти всегда (Блокнот). Для `.pdf` —
  если стоит Adobe Reader или Edge с ассоциацией на PDF. Для `.docx` — нужен
  Word (или LibreOffice с зарегистрированным print-verb). Если verb-а нет,
  `ShellExecute` вернёт код ≤32 — это должно корректно всплыть как
  `PrintError` с этим кодом, а не тихо ничего не напечатать. Стоит
  протестировать хотя бы `.txt`, `.pdf` и один офисный формат.

### 4. Печать с нестандартными настройками

В интерфейсе выбрать не-дефолтные значения (например, `A5` вместо `A4`,
"Черновик" вместо "Обычное", двустороннюю печать, если доступна), напечатать
и визуально сверить с реальным результатом. Это самая сложная для проверки
часть — до конца автоматически не верифицируется, нужен человек с
принтером в руках.

## Известные компромиссы (не баги, а осознанные решения — не переделывать без причины)

- `_apply_devmode()` меняет **настройки принтера по умолчанию**, а не
  настройки конкретного задания — это стандартный (и по сути единственный
  простой) способ передать параметры при печати через `ShellExecute` на
  Windows. При параллельной печати нескольких заданий на один принтер
  теоретически возможна гонка настроек — не критично для одного домашнего
  принтера, при котором это и задумывалось.
- Требует прав `PRINTER_ALL_ACCESS` на принтер. Если тестирование покажет
  `Access Denied` у обычного пользователя — заменить на менее строгий набор
  прав (`PRINTER_ACCESS_USE | PRINTER_ACCESS_ADMINISTER`) или сделать так,
  чтобы при отказе доступа сервер тихо печатал с текущими настройками
  принтера вместо падения задания в `failed`.

По каждому пункту чек-листа — сработало / не сработало (с точным текстом
